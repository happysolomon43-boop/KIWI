## 3. Implementation changes

### Durable event/runtime foundation

Added:

- `teaching/runtime/constants.js`
- `teaching/runtime/time-projection.js`
- `teaching/runtime/reconciliation.js`
- `teaching/runtime/postgres-event-store.js`
- `teaching/runtime/durable-event-runtime.js`
- `teaching/runtime/index.js`

Key behavior:

- due events are persisted before execution;
- browser tabs are never authoritative time owners;
- server timestamps are the source for countdown/timer projections;
- durable claims use bounded leases and `FOR UPDATE SKIP LOCKED`;
- idempotency keys prevent duplicate authoritative execution;
- expired claims become recoverable retry work;
- every academic event handler must reconcile current authoritative state before acting;
- reconciliation distinguishes actionable, already-satisfied, superseded and fairness-recovery-required states;
- exhausted KIWI-side execution failures enter explicit fairness recovery instead of fabricating a student penalty;
- no D02 runtime object owns Course scope, Scheduler truth, Gradebook, SKM, Assessment, Attendance, Request or Progression truth.

### Event contracts

Changed:

- `teaching/events/contracts.js`
- `teaching/events/names.js`

D02 adds distinct authoritative due-event vocabulary for:

- Class start due;
- break end/expiry due;
- assessment expiry due;
- Class end due;
- approved Request effective time due.

Event envelopes now distinguish commands, committed domain events, scheduled due events, intelligence results and operational/recovery events. Authenticated input cannot masquerade as an authoritative committed/system-time event.

Event payloads are bounded routing metadata rather than an alternate source-content or academic-state store.

### Central AI execution and validation

Added:

- `teaching/ai/contracts.js`
- `teaching/ai/failure-policy.js`
- `teaching/ai/output-validation.js`
- `teaching/ai/central-orchestrator-boundary.js`
- `teaching/authority/owners.js`
- `teaching/authority/deterministic-precedence.js`
- `teaching/authority/commit-gateway.js`

Invariants:

- Teaching feature/domain code does not call a provider SDK directly;
- model work enters through the injected central KIWI AI Orchestrator runner only;
- T0 responsibilities are rejected from the model path;
- T2–T4 require schema and domain validation before a result can receive the trusted internal validation brand;
- deterministic-authority checks may veto schema-valid/model-plausible output;
- the authoritative commit gateway accepts only branded validated results;
- the gateway can only hand accepted output to a registered authoritative owner service;
- the gateway itself owns no academic truth.

D02 does not create the D03 Capability Registry runtime, prompt-family dispatcher, Constitution binder or Teaching AI route manifest.

### Failure behavior

Authority-aware failure policy implemented:

- T0 — deterministic state does not depend on AI;
- T1 — safe constrained communication fallback may be used;
- T2 — invalid/failed interpretation cannot mutate durable evidence;
- T3 — invalid/failed planning/generation remains draft/pending;
- T4 — invalid/failed judgment cannot finalize an official mark.

All KIWI-caused failure paths are non-punitive.

### Context security

Added `teaching/security/context-lanes.js`.

It structurally separates:

- trusted authoritative state;
- permission constraints;
- provenance-linked academic content;
- explicitly untrusted Subject/upload/student/source/retrieved content.

Formal-marking context rejects irrelevant attendance, Teacher Personality, reputation, prior GPA, unrelated marks and behavioral history unless an approved academic policy explicitly requires an exception.

### Observability

Added `teaching/observability/postgres-execution-telemetry.js`.

Safe telemetry includes execution/event correlation, responsibility key, intelligence class, authority ceiling, central task/model identifier, contract/schema versions, validation outcome, rejection/safe-failure reason and eventual authoritative-owner mutation reference.

It does not persist hidden chain-of-thought, prompt bodies, student response bodies, assessment answers, source passages, secrets or tokens.

### Accessibility

Added:

- `teaching/accessibility/baseline.js`
- `docs/teaching/accessibility/d02-baseline.md`

Minimum reusable primitive contract:

- keyboard operability;
- semantic structure;
- visible focus;
- status not encoded by color alone;
- text-scaling/reflow safety.

### Threat model

Added `docs/teaching/security/d02-threat-model.md`.

Threats addressed at the D02 layer include grade/academic-record tampering paths, assessment leakage boundaries, RLS/Data API bypass, privilege escalation, prompt/content injection, stale/duplicate event execution and invalid/outage model behavior.

### Backend composition

`index.js` now composes the D02 Teaching runtime with the existing server-side PostgreSQL connection and the central KIWI AI Orchestrator.

Runtime initialization is fail-closed: if the D02 operational schema is unavailable, the Teaching due-event worker stays stopped. The backend does not substitute browser time or an in-memory academic-time authority.
