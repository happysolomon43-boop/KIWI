# Rescheduled Class: validated lesson and partial preparation inheritance

## Contract

An approved D10 `SINGLE_CLASS_RESCHEDULE` normally cancels the unstarted old Class and materializes a replacement under the newly approved D09 timetable. This is correct for academic and attendance authority but must not discard compatible AI work. The request now publishes a **specific, unique** `from_class_id → to_class_id` routing hint, only when the replacement exactly matches the request's approved Course and new start/end times. No other Class on the semester-wide rebuilt timetable is eligible to inherit that Class's preparation.

D11's existing `REQUEST_APPLIED → CLASS_PREPARATION_RECONCILE` flow carries the hint. The D11 owner locks and re-reads both Class rows, the latest Course Plan and timetable slots. Before any copy it verifies student and Course identity, original cancelled/unstarted Class, replacement SCHEDULED/ACTIVE/APPROVED and future, matching formal request and timetable lineage, unchanged Course state, identical scheduled learning-unit scope, both Class session histories empty, and the current Course Plan. Missing or stale inputs take the normal fresh preparation path.

**Already validated lesson**: for identical duration and a fully valid old Blueprint (including old Blueprints correctly superseded after the reschedule), D11 runs the **same deterministic Blueprint validator** against the replacement Class. Only after it passes does the D11 owner transaction save an entirely new validated Blueprint, using the new Class, timetable, Course and Plan versions. The old Blueprint is not mutated, resurrected, or linked as the target's `preparation_ref`. New `generation_provenance` and an academic audit contain the source Blueprint, source Class, approved Request and zero new AI calls. Empty successor PPL workspaces are superseded to avoid the start Controller mistakenly treating an inherited validated Blueprint as unfinished preparation.

**Still preparing / changed duration**: a previous validated provisional artifact, or a previous validated Blueprint whose duration changed but whose complete content still satisfies the new deterministic duration and unit-scope rules, may be transferred only as a **new PPL artifact**. New target input bundles, component dependencies and content digests are created; no old authority pointers are reused. The new workspace may advance through the canonical already validated Skeleton/Structured/Candidate gates, but it is NEVER given FINALIZED/HANDED_OFF or a published D11 Blueprint by this path. Remaining PPL stages proceed through the real D11/D05/D28/D31 validated model pipeline.

**Safety and idempotency**: no Class session, attendance, grades, due-event history or timetable is copied. The validated Blueprint insert and partial artifact copy use D11's existing authority/version fences inside one transaction. Destination Blueprints/artifacts block duplicate copies. Superseded old AI jobs cannot publish to the new Class. The old Class and lesson content remain available as history, and D11's ordinary cancellation/invalidation sweep remains enabled.

## Limitations and regressions

A stale or absent source, a changed Course Plan/course version, an invalid candidate, a changed learning-unit set, an already-started Class, or a replacement that has reached its start time falls back to normal preparation rather than silently reusing unsafe content. Some changed-duration lessons may require new model calls because their original segment/reserve allocation no longer validates against the new Class window. That is deliberate and **not** a failure to carry forward compatible content.
