# Teaching Release Scope Baseline

## Internal Alpha

The first internal Alpha is intentionally the smallest real Teaching vertical slice, not a mini-version of the whole institution.

Acceptance target:

`existing Subject → Course Plan → one scheduled Class → Teacher-led lesson with at least two Teach/Check cycles → persisted state → Class Summary → updated learning evidence`.

Alpha must prove the core loop and authority boundaries. It is not allowed to pull downstream systems forward merely because they are attractive.

Explicitly outside the first kernel milestone unless required to validate the core loop: GPA, resits, deep KIWI integrations, voice/avatar and other downstream institutional/product completeness systems.

## Basic Teaching Beta

Basic Teaching Beta expands the credible recurring academic life around the core loop, including:

- recurring schedule/classes;
- Student Knowledge Model continuity;
- Homework/independent Work;
- attendance/lateness basics;
- basic Tests.

It still does not imply the entire assessment/grading institution is complete.

## Assessment / Grading Beta

Assessment/grading Beta is a separate scope and acceptance boundary. It requires the formal Assessment domain, locked packages, response shell, assessment types, marking/moderation/appeal behavior and Gradebook ownership according to later deliveries.

The distinction prevents “Teaching Beta” from being treated as proof that high-stakes grading is ready.

## Release discipline

No model-backed Teaching route is production-qualified merely because Alpha/Beta UI works. D30 owns empirical route qualification. D31 owns final production authorization.
