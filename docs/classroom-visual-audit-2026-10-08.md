# Classroom image and diagram audit — 8 October 2026

The production Classroom visual pipeline is **not complete**. Board rendering and validated visual adapters exist, but they are not evidence of Teacher-triggered generation.

## Verified connections

- `services/ai/runtime.js` exposes central image generation and structured diagram rendering through the AI orchestrator. Cloudflare image generation and Kroki diagram rendering have validated response contracts, output limits, caching, and transport cancellation support.
- TPF-08 describes Board use for diagrams and other persistent instructional representations.
- `teaching/d14/visual-board-contract.js` adapts generated image/diagram responses into local-asset Board blocks. Generated imagery is explicitly supplementary illustration; structured diagrams carry their own provenance. Diagrams are sanitized before adaptation.
- D14 publication validates Board blocks and writes the Teacher message and Board scene/items in one transaction, with current Class/Course/Plan/Blueprint/Timetable authority fences.
- The Classroom renders image and diagram blocks, supplies alt text, and supports Board-to-Notebook references.

## Missing production connections

- The visual Board adapters have no production callers; current calls are in unit tests.
- The D14 raised-hand Teacher schema only returns answer/defer/decline text. It neither declares a visual request nor passes Board blocks to publication.
- No durable materialization and authenticated retrieval path connects generated bytes/SVG to the local KIWI asset reference required by the Board contract. Setting an image URL alone does not supply this connection.
- The generic TPF-08 instruction does not give the raised-hand Teacher an executable image/diagram request contract, available-capability state, or success/failure acknowledgement.
- Production read-only audit found **zero** Board items with image or diagram block types at the time of inspection. This supports the absence of observed use; it does not by itself prove a provider outage.

## Completion requirements

A separate implementation must connect validated Teacher visual intent to the centrally governed capabilities, bind generation to exact current lesson authority with revocation/cancellation, enforce bounded budgets and idempotency, persist assets privately, retrieve them with student/Class authorization, publish Board blocks through D14's atomic fence, and give both Teacher and student a truthful fallback when unavailable. Verify actual provider output, asset retrieval, Board display, historical viewing, and protected-activity refusal before claiming production readiness.

This audit does not claim that image or diagram generation works end to end in Classroom.
