# D29 comprehensive academic QA

This package owns QA evidence only. It never becomes an academic truth owner. Every passing scenario records its canonical task/invariant mapping, fixture and source version, actor/time assumptions, expected owner transition, persistence, security, replay/failure behavior and actual result. A rendered screen alone cannot pass.

The harness composes accepted D01–D28 interfaces. It does not empirically qualify AI routes (D30) and does not authorize production release (D31). Fixtures are namespaced and destructive testing is limited to integration/staging targets.

`scenarios.js` is the executable 50-task acceptance catalogue. Each entry binds one frozen D29 task to a named assertion in its authoritative predecessor owner. `npm run verify:teaching:d29` validates the catalogue and then executes every referenced owner test file. A renamed/deleted assertion, a missing file, or any failing owner suite fails the delivery gate; task counting alone cannot pass it.

Readiness is independently fail-closed. All five metric inputs (at least 20 live-Class latency samples, autosave reliability, assessment persistence, scheduler failure rate, and confirmation that grading disagreements received review) are required, as are authoritative-state, audit, and applicable security evidence for every PASS.

Current integration provenance reconciliation: the D28→D29 handoff reported four D29-named integration migrations, but the integration migration ledger observed at D29 start on 2026-10-04 contained none of them and no D29 Git branch, PR or commit existed. This delivery therefore starts from the observed clean D28 integration head and records the earlier entries as historical interrupted drift rather than reapplying unknown SQL.
